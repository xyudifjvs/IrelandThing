# Coordinator portfolio and daily digest

Mount `createPortfolioRouter({ listEmailWork })` from `packages/matters/src/portfolio/router.ts` at `/api/v1/portfolio`. Inject C07's `listEmailWork` from `packages/communications/src/email-work.ts`. The router serves the pending intake list, transaction filters, due work, Calendar range and email attention. The Overview uses the existing roster, private to-do and intake deletion routes. Reminder links and the email attention notice open the transaction's Emails tab through `?tab=emails`. Agent links use the roster's `?agent=` route.

The worker keeps the existing private reminder handler and scheduler. C00 also retires the previous per-intake notification handler, including queued work. The digest takes the last accepted or empty window's cutoff through the current scheduled cutoff. The first window begins at the previous scheduled weekday cutoff. Both use the configured civil time, which defaults to 8 a.m. America/New_York. The lower bound is inclusive and the upper bound exclusive. This includes Friday and weekend submissions received after Friday's cutoff even if they are processed before Monday. Deleted submissions are omitted. Ireland should confirm this window, cutoff and email wording.

The intake writer holds a shared advisory lock from the receipt timestamp through commit. The worker uses the same PostgreSQL clock to schedule the cutoff. Its receipt query acquires the exclusive lock before reading committed rows, so a receipt stamped before the cutoff stays in that window even when its transaction commits after digest preparation begins. This protocol requires the matching API and worker versions.

A pending window is persisted before sending. The approved transport request is encrypted in the private job while a delivery result is unresolved. Retries use the same request and provider idempotency key. The request is removed after acceptance, an explicitly empty window or a definite provider rejection. A window with a failed and still unresolved dispatch remains pending for reconciliation. The sender stops retrying outside the provider idempotency window. Reconcile a failed dispatch against Ireland's provider history before advancing a cursor or releasing the existing window. No provider actions were taken during C12 development.

C12 retained the existing private reminder recipient and delivery gates. The browser validation uses mocked API traffic. The portfolio and digest suites use a disposable local PostgreSQL database and synthetic email transport. Composition, independent review and Ireland's real delivery verification follow this checkpoint.
