## Findings

1. **P2. A contract uploaded during creation cannot be shared after confirmation.** I checked an owner-only staged contract, attached it with C05's `attachReviewDocuments` from `0a90322`, and recorded the confirmed review. The document correctly retained `creationReviewId` as well as the published `matterId`. A coordinator's `PATCH /api/v1/documents/:id` to enable the agent switch returned `409 REVIEW_DOCUMENT_PRIVATE`. The condition at `packages/documents/src/router.ts:207` treats all documents with a review ID as still staged. Limit this guard to documents that remain unpublished and preserve the review's source link. Cover the upload → confirm → change sharing sequence.
2. **P2. A new coordinator upload to a historical file starts visible to the agent.** With an active `checklistVersion: null` file, the coordinator sent a normal multipart upload without any sharing selection. It returned `visibility: "agent"` and `shareWithAgent: null`. The assigned agent's direct View returned `200` before the coordinator used either switch. `packages/documents/src/upload.ts:30` and `:231` leave new uploads to historical files on the legacy default. Apply actor-based private defaults to every new file upload and retain legacy fallback for pre-existing records.
3. **P2. An authenticated document read can deliver bytes after account access is withdrawn.** I paused storage reads after real Better Auth authorization and committed each of three changes before storage returned. A revoked agent, an agent downgraded to client while viewing an agent-only document, and an agent whose HTO membership and approved agreement were withdrawn each received `200` and the exact synthetic PDF bytes. A subsequent request returned `403`, `404`, and `403`, respectively. `packages/documents/src/read.ts:64` checks audience again but `packages/documents/src/access.ts:88` uses the request's captured role and entitlement. Revalidate current account access and effective role before returning content, including ZIP entries. The bearer path correctly denied a link revoked during storage access.
4. **P2. A closed ZIP can disclose a filename after its document audience was revoked.** A completed agent ZIP contained two allowed PDFs and omitted the client-only document. I repeated the request and disabled the second document's agent switch while the first file's storage read was in progress. The server had already committed `200` when it wrote the second entry's filename into the ZIP local header, then aborted on the second file's access check. The client received 142 bytes, including `PROOF (2).PDF` and none of that file's content. `packages/documents/src/archive.ts:45–47` lets JSZip stream each local header before the async document read authorizes the entry. Delay entry metadata until that entry's current authorization succeeds.
