# Intake source preparation and conflict review

`prepareIntakeReview(matterId, submissionId)` prepares durable per-source/version proposal records after the intake transaction commits. The worker can call it after the existing gift-record handler. It never invokes a model or retrieves Dotloop. Readable contract sources queue extraction only through an approved OpenRouter privacy route and a current unrevoked coordinator. `AI_REVIEW_OWNER_ID` can select the owner explicitly; otherwise exactly one eligible coordinator must exist. Missing providers, unreadable sources and missing contracts produce truthful unavailable metadata and private manual-review/retrieval tasks, not sample findings or indefinitely queued reviews. Retry identity survives extraction processing.

Extraction records exact source quotes, document/version IDs and page references. Actual contract timing clauses retain their count, direction, calendar definition and anchor evidence. Deterministic dates are only proposed when those inputs are supported; there are no jurisdictional or brokerage offset defaults. Unclear calendars and anchors remain for Ireland to resolve.

Conflicts among document values, intake values and confirmed facts are saved in `AIProposal.result.conflicts`, with unresolved markers in `Matter.details.sourceConflicts`. Each conflict has `key`, `kind`, `field`, `label`, `reason` and quoted candidates. Approval requires explicit final values and reasons; selected nonconflicting facts are optional and never applied automatically. Confirmed facts merge with earlier approved values, preserving the original intake and proposal history. Template preparation/sending must remain blocked while any source-conflict marker remains.

`POST /api/v1/ai/reviews/:id/resolve-conflicts` is an explicit coordinator correction path for stale-source conflicts. It takes the current matter revision and all saved conflict resolutions. It records manual choices and the latest source-version identities without claiming that the old extraction is current. Ordinary extraction approval still rejects changed source versions. Historical candidates and resolution audit records remain available.

All validation for this change used synthetic local records and mocked providers. Connected operator-account plugins are not production provider accounts. Provider setup, credentials and activation belong on Ireland's own deployment/account environment.
