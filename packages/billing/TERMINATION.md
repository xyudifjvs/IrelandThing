# Pre-closing service-checkout termination

Service fees are due at closing, with no service fee if the transaction terminates before closing. A replacement is a new linked transaction with its own billing. Paid, refunded and disputed records retain their original amounts and snapshots; this workflow performs no refunds or new charges.

`queueTerminatedServiceCheckouts(tx, actor, matterId)` composes with the existing matter-change hook. It acts only on an explicitly recorded `details.termination.beforeClosing === true` and a terminated matter (or its later archived state). It changes unpaid issued requests to `void_pending` and creates one durable `billing.expire_checkout` job per saved session. Its payload contains only `paymentOrderId`. No-session unpaid requests cancel locally; a creation that may already be in flight is recorded as an uncertain provider outcome.

`expireTerminatedServiceCheckout(payload, provider = verifiedStripe)` uses the existing Ireland-account and environment checks. It verifies the saved session ID, payment-order metadata, amount, currency and test/live mode before changing a provider session. Stripe permits expiration only for an **open** Checkout Session. Already-expired responses are idempotent success; completed or paid responses and settlement races require reconciliation. See [Stripe’s expiration reference](https://docs.stripe.com/api/checkout/sessions/expire).

Expiration has a stable provider idempotency key. A provider error is followed by a fresh read; an error alone is never treated as proof of expiration. Local cancellation follows a verified expired/unpaid result. A concurrent paid/refund/dispute update retains its financial status and adds a reconciliation marker. Failed or unconfigured provider attempts leave a visible non-payable internal request and retry/review evidence.

New coordinator service requests require a confirmed file in Closing/Closed; no calendar-date trigger is inferred and intake never creates checkout. Retained historical requests replay from their saved records. Coordinator creation and agent resumption recheck the current matter/payment state. If termination happens while a new Stripe session is being created, the late session is retained and queued for expiration while its URL is withheld. An existing checkout read also rechecks state before returning its URL. An already distributed external URL is invalidated only after the provider accepts expiration; internal denial does not itself revoke that URL.

No production account is connected or activated by this code. Plugins connected in Carson’s Codex account are not Ireland’s production accounts. Actual provider verification, sandbox acceptance and production activation belong in Ireland’s Codex/account context on her laptop. The local tests use injected synthetic Stripe adapters only. They cover duplicate jobs, no-session cancellation, protected history, session/environment mismatches, provider retry, paid/complete races, and both late-created and late-read checkout URLs.
