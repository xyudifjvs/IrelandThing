# File and milestone approval boundaries

New agent submissions carry `stage=pending_review` and `details.fileReview.status=pending`. The agent can read its receipt/status; task and deadline arrays stay empty until Ireland confirms. Clients and bearer checklists cannot open a pending file. Existing historical records without the new marker retain their behavior.

Coordinator-only `GET /api/v1/matters/:id/file-review` returns the current revision, processing/source-conflict blockers and the exact unresolved-date acknowledgements required for confirmation. `POST /api/v1/matters/:id/confirm-file` accepts `expectedRevision` and optional `acknowledgedUnresolved` rows with the returned IDs/labels plus a reason. Explicitly unresolved dates become unknown/null dates with durable private follow-up tasks and evidence history. Source conflicts must be resolved first. Confirmation applies the saved workflow and opens the active file. Later approval of an unresolved date completes its follow-up; no date is invented.

Tasks remain single canonical records. Visibility values are `coordinator` (private), `agent` (agent only), `client_only` (client/public only) and historical `client` (both audiences). Optional validated `note` (up to 1,000 characters) and timezone-bearing `appointmentAt` are stored in task details and explicitly projected to authorized viewers; other private task details do not enter agent/client/public projections. Agent reads also omit source-review `confirmedFacts`, workflow definitions and conflict internals. Historical statuses remain readable. Content changes are coordinator-only; scoped agents may manage client checklist links, and clients remain read-only.

Deadline create/patch accepts the same four values as top-level `visibility`, stored in existing `details.visibility`. New standalone manual/source-confirmed/unresolved dates default to private; historically unmarked standalone rows retain their prior readability. Workflow-linked dates inherit their canonical task audience, while an explicit deadline audience can only narrow it. Associations use the workflow key, or the matching canonical title/definition when no key exists. Missing or duplicate linked associations fail closed. `getMatter`, `listMatters` and the public checklist share this projection. A hidden linked date also clears the derived due date on a still-visible task. Coordinator reads return effective `visibility`, `linkedToTask` and optional `inheritedVisibility`; a date-only correction retains its existing audience. Agent/client APIs cannot change these values.

Only confirmed rule deadlines can supply authoritative task dates. Calculations from approved anchors remain proposals until approval, dependency order is respected, and changed upstream anchors withdraw downstream authority. Explicit quoted-source overrides are preserved with audit history. There are no default state/brokerage date offsets.

Write authorization inside an existing transaction re-reads the scoped matter after acquiring its row lock. A writer that commits while another reviewer waits cannot leave that reviewer checking a stale revision or conflict set. A deleted row fails with the same generic not-found response.
